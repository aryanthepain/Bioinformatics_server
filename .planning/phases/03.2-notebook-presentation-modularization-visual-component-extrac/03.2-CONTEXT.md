# Phase 03.2 Context: Notebook Presentation Modularization & Visual Component Extraction

## Context Overview
The user requested decluttering `Quaternary_Structure.ipynb`, which had accumulated hundreds of lines of inline HTML/CSS formatting strings, JavaScript DOM injections, and input validation regexes in code cells (notably Cell 2 and Cell 5).
The objective is to extract these functions into a dedicated presentation module (`quaternary/presentation.py`), maintain a clean functional design where renderers return `HTML` objects rather than calling `display()`, streamline the notebook into an executive-ready demo with explicit `display(render_*(...))` calls, and author comprehensive, isolated unit tests for every individual function.

## Locked Decisions

### D-01: Module Architecture & Purity
- **Dedicated Module**: All visualizers, HTML formatters, JSON inspectors, and pre-flight input validators are placed strictly in `quaternary/presentation.py`.
- **Clean Pipeline Facade**: `quaternary_pipeline.py` remains strictly focused on the biological/computational engine, avoiding UI/HTML presentation pollution.
- **Pure Function Contract**: Every `render_*` and `show_json` function strictly constructs and **returns** an `IPython.display.HTML` object. The function itself does **not** invoke `display()`.
- This enables deterministic testing without mocking `display()` and gives callers full control over display lifecycle.

### D-02: Extracted Function Signatures & Behaviors
1. `validate_target_input(target_input: str) -> tuple[bool, str]`: Pre-flight regex validation of UniProt accession or FASTA sequence.
2. `render_validation_status(is_valid: bool, msg: str) -> HTML`: Returns styled HTML banner indicating validation pass/fail.
3. `show_json(data: Any, max_depth: int = 1) -> HTML`: Returns VS Code dark theme tree viewer using `renderjson.min.js` and unique DOM container id.
4. `render_quaternary_summary_card(output: QuaternaryStructureOutput) -> HTML`: Returns executive overview card with oligomeric status, stoichiometry, and segregated confidence provenance.
5. `render_component_identity_table(output: QuaternaryStructureOutput) -> HTML`: Returns macromolecular component table distinguishing target subunit from partner complexes.
6. `render_interface_contact_table(output: QuaternaryStructureOutput) -> HTML`: Returns biophysical contact table for buried surface area, $\Delta^i G$, H-bonds, salt bridges, or empty fallback banner.
7. `render_dynamic_equilibrium_display(output: QuaternaryStructureOutput) -> HTML`: Returns multi-assembly equilibrium display across crystal forms.
8. `render_functional_inference_card(output: QuaternaryStructureOutput) -> HTML`: Returns executive bio-mechanistic card showing inferred molecular function, biological process, quaternary mechanism hypothesis, and GO terms.
9. `render_evidence_coverage_dashboard(output: QuaternaryStructureOutput) -> HTML`: Returns audit table listing queried databases, hit badges, and explicit scientific uncertainties.

### D-03: Notebook Streamlining & Presentation Layout
- **Consolidated Imports (Cell 2)**: Cell 2 contains a single consolidated import of all presentation utilities:
  ```python
  from IPython.display import display
  from quaternary.presentation import (
      validate_target_input,
      render_validation_status,
      show_json,
      render_quaternary_summary_card,
      render_component_identity_table,
      render_interface_contact_table,
      render_dynamic_equilibrium_display,
      render_functional_inference_card,
      render_evidence_coverage_dashboard,
  )
  ```
- **Explicit Display Calls**: In presentation cells, visualizers are invoked explicitly: `display(render_quaternary_summary_card(output))`, `display(show_json(output.model_dump()))`.
- **Pre-flight Validation (Cell 5)**: Uses `is_valid, msg = validate_target_input(TARGET_PROTEIN)` followed by `display(render_validation_status(is_valid, msg))`.
- **Zero Inline Boilerplate**: Multi-page HTML string templates and regex blocks are completely removed from notebook cells.

### D-04: Isolated Granular Unit Test Suite (`tests/test_presentation.py`)
- Author `tests/test_presentation.py` dedicated to verifying each function in isolation:
  - `validate_target_input`: valid accessions (`P0A6F5`, `P01308`, `P44101`), valid FASTA, empty string, malformed strings, non-IUPAC characters, header-only FASTA.
  - `render_validation_status`: success banner (green, checkmark) vs failure banner (red, error message).
  - `show_json`: handles Python dicts, Pydantic models (e.g. `Stoichiometry`), generates unique container IDs (`json_viewer_`), and embeds `renderjson.min.js`.
  - `render_quaternary_summary_card`: asserts oligomeric state, stoichiometry, and segregated confidence provenance.
  - `render_component_identity_table`: validates target subunit and partner complex tables.
  - `render_interface_contact_table`: validates biophysical contact metrics ($\text{Å}^2$, $\Delta^i G$, H-bonds, salt bridges) and empty fallback banner.
  - `render_dynamic_equilibrium_display`: validates alternative crystal form assemblies.
  - `render_functional_inference_card`: verifies molecular function, biological process, confidence badge, and GO terms.
  - `render_evidence_coverage_dashboard`: verifies database hit status badges and uncertainty disclosures.
