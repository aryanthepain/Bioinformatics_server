# Phase 03.2 Research: Notebook Presentation Modularization & Visual Component Extraction

## Codebase Scouting & Baseline Invariants

### 1. Existing Notebook Generation Architecture
- **Generator script**: `scripts/build_notebook.py` programmatically builds `Quaternary_Structure.ipynb` using `nbformat.v4`.
- **Boilerplate hotspots**:
  - `build_wave_2_cells()` (Line 101): Currently injects a 250-line code block into Cell 2 containing full implementations of `show_json`, `render_quaternary_summary_card`, `render_component_identity_table`, `render_interface_contact_table`, `render_functional_inference_card`, `render_dynamic_equilibrium_display`, and `render_evidence_coverage_dashboard`.
  - `build_wave_1_cells()` (Line 155): Injects `validate_target_input` and `render_validation_status` function definitions into Cell 5.
- **Refactoring Strategy**:
  - Relocate all these implementations to `quaternary/presentation.py`.
  - In `build_notebook.py`, replace the multi-page code blocks with clean, single-statement imports:
    `from IPython.display import display`
    `from quaternary.presentation import (...)`
  - Re-execute the notebook to generate a pre-executed, clean, presentation-grade `.ipynb`.

### 2. Functional Purity & Return Value Contract
- Currently, notebook visualizers both construct HTML and call `display(HTML(...))`, returning `None`.
- **Target Contract**:
  - Render functions strictly construct and **return** an `IPython.display.HTML` object.
  - The functions do **not** invoke `display()` internally.
  - The notebook caller explicitly wraps calls: `display(render_*(output))`.
  - This completely eliminates the need for `mock_display` in tests and allows pure, deterministic assertions directly on `html_obj.data`.

### 3. Test Alignment & Verification Plan
- **New Test Suite (`tests/test_presentation.py`)**:
  - Independent unit tests for each of the 9 functions.
  - High-confidence assertions on HTML classes, colors, badge text, table headers, and fallback strings.
  - Edge cases: uncharacterized targets without experimental/homology evidence, proteins with empty multimer interfaces, malformed accession regex, non-IUPAC characters in FASTA, Pydantic models vs dicts in `show_json`.
- **Scaffold & Visuals Test Updates**:
  - `tests/test_notebook_scaffold.py`: Check that `Quaternary_Structure.ipynb` imports `validate_target_input` from `quaternary.presentation` and executes it in Cell 5.
  - `tests/test_notebook_visuals.py`: Check that `Quaternary_Structure.ipynb` imports visualizers from `quaternary.presentation` in Cell 2, and that visualizers output valid HTML without needing code cell extraction hacks.
- **E2E Test**: `tests/test_notebook_e2e.py` runs headless notebook execution against offline fixtures, verifying 100% pass rate.
